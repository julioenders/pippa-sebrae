🏠
Portal PIPPA
Hub central de acesso a todas as ferramentas do observatorio com filtro por perguntas norteadoras
100% Estatico HTML Unico
▸
📐 Arquitetura
  • Arquivo unico: pippa-portal/index.html (~589 linhas)
  • 100% estatico — sem APIs, sem fetch(), sem build steps
  • Layout: top-nav sticky + hero com stats + search bar + sidebar (320px) com perguntas + grid de cards
  • Responsivo: colapsa para coluna unica em telas < 768px
  • Vanilla HTML/CSS/JS — sem nenhuma biblioteca externa (nem Chart.js)
⚙️ Configuracao

Tres arrays JS controlam todo o conteudo:

ArrayCamposFuncao
TOOLSid, nome, subtitulo, accent, icon, url, descricao, features[], destaqueDefine cada ferramenta e seu card
QUESTIONStexto, ferramentas[], macroPerguntas norteadoras que filtram os cards por ID
MACRO_TEMASkey, nome, icone6 grupos tematicos que agrupam as perguntas
🔑 Funcionalidades
  • Busca: Filtro de texto em tempo real (nome, subtitulo, descricao, features)
  • Filtro por macro-tema: Clicar no header do grupo filtra todas as ferramentas do tema
  • Filtro por pergunta: Clicar em uma pergunta especifica filtra as ferramentas mapeadas
  • Cards expandiveis: Clique revela descricao completa, tags de features, destaque e link de acesso
  • Contadores dinamicos: "Visiveis" e "Exibindo X de Y" atualizam em tempo real
  • Links externos: URLs com http abrem em nova aba; URLs relativas navegam no mesmo contexto
📚 Dependencias
  • Google Fonts (Inter) via CDN — unica dependencia externa
  • Sem Chart.js, sem frameworks, sem build tools
🚀 Passo a Passo de Replicacao
  • Copiar index.html para o servidor
  • Garantir que as pastas-irmãs das ferramentas existam nos caminhos relativos corretos (ex: ../pippa-emendas/, ../pippa-legislativo-dashboard/)
  • Para adicionar uma ferramenta: inserir objeto no array TOOLS com id, nome, url, etc.
  • Para adicionar perguntas: inserir no array QUESTIONS com ferramentas[] mapeando IDs de tools
  • Para criar novo macro-tema: inserir no array MACRO_TEMAS com key correspondente
  • Atualizar os stats do hero (Ferramentas, Fontes, Cubos) manualmente no HTML
⚠️ Problemas Conhecidos
Os stats do hero (Ferramentas, Dashboards, Fontes, Cubos) sao hardcoded no HTML e nao derivam dos arrays JS. Ao adicionar/remover ferramentas, e necessario atualizar manualmente esses valores. Links relativos dependem da estrutura de pastas-irmãs no deploy.

PIPPA Emendas Parlamentares
Painel de inteligencia sobre execucao de emendas parlamentares federais
4 APIs Pipeline Python Chart.js HTML Unico
▸
📐 Arquitetura
  • Arquivo principal: pippa-emendas/output/pippa_emendas_completo.html (~1.46 MB)
  • HTML self-contained com dados JSON embarcados inline (~694K de dados)
  • Gerado por pipeline Python (scripts/gerar_dashboard.py → html_renderer.py)
  • Backend opcional: api.py (FastAPI, porta 8050) para atualizacao em tempo real
  • 7 abas: Estados, Municipios, Autores, Partidos, Serie Temporal, Setores, Qualidade
🔗 Fontes de Dados
FonteURL BaseAutenticacaoDados
Portal da Transparencia (CGU)portaldatransparencia.gov.brNenhumaCSV ZIP com todas as emendas (~94K registros)
Tesouro Transparenteapidatalake.tesouro.gov.brNenhumaCSV de transferencias (validacao cruzada)
Camara dos Deputadosdadosabertos.camara.leg.br/api/v2NenhumaDeputados por legislatura (partido/UF)
Senado Federallegis.senado.leg.br/dadosabertosNenhumaSenadores por legislatura (partido/UF)
📚 Dependencias
  • Frontend: Chart.js 4.4.4 + chartjs-chart-treemap 2.3.1 (CDN jsDelivr)
  • Python: pandas, requests, fastapi, uvicorn, python-multipart
⚡ Pipeline de Dados

Pipeline de 5 fases em scripts/pipeline.py:

  • Collect — Download dos CSVs do Portal da Transparencia e Tesouro + chamadas REST para Camara e Senado
  • Enrich — Fuzzy-match de autores com deputados/senadores para enriquecimento de partido e UF
  • Filter — Filtragem opcional por ano
  • Cross-validate — Comparacao Portal vs Tesouro, flags de divergencia > 5%/15%
  • Persist — Gera arquivos Parquet com agregacoes + JSON de qualidade

O gerador de dashboard (gerar_dashboard.py) le os Parquets e embarca tudo em um unico HTML.

🚀 Passo a Passo de Replicacao
  • Clonar o repositorio pippa-sebrae
  • Instalar dependencias: pip install pandas requests fastapi uvicorn python-multipart
  • Executar pipeline: python scripts/gerar_dashboard.py (baixa ~100 MB de dados, leva alguns minutos)
  • O dashboard sera gerado em output/pippa_emendas_completo.html
  • Abrir o HTML diretamente no navegador (funciona offline com dados embarcados)
  • Opcional: Para modo live-refresh, executar python api.py e acessar http://localhost:8050
⚠️ Problemas Conhecidos
O UUID do recurso do Tesouro Transparente no CKAN e hardcoded e pode mudar quando o dataset for republicado. Verificar periodicamente se o endpoint continua ativo.

Radar de oportunidades de licitacoes para micro e pequenas empresas
1 API Caches Embarcados Chart.js HTML Unico
▸
📐 Arquitetura
  • Arquivo unico: pippa-compras-dashboard/index.html (~6.8 MB, 131K linhas)
  • 5 views: Landing, Compras (PNCP live), PDDE, PNAE, Execucao Orcamentaria
  • Dados de PDDE/PNAE/Execucao embarcados como caches JSON inline (responsaveis pelo tamanho do arquivo)
  • Aba Compras faz consulta live a API do PNCP
🔗 Fontes de Dados
FonteURL BaseAutenticacaoDados
PNCP (Portal Nacional de Contratacoes)pncp.gov.br/api/consulta/v1/contratacoes/publicacaoNenhumaLicitacoes publicadas (5 pags x 5 modalidades)
A API do PNCP e acessada via proxy CORS api.allorigins.win (gratuito, sem garantia de disponibilidade). Em ambiente corporativo, substituir por proxy proprio (Nginx, Cloud Functions).
📚 Dependencias
  • Chart.js 4.4.4 (CDN jsDelivr)
  • Google Fonts (Inter)
  • Sem dependencias Python — dashboard puramente client-side
⚡ Pipeline de Dados

Nao ha pipeline automatizado. Os caches de PDDE, PNAE e Execucao sao arrays JSON inseridos manualmente no HTML. Para atualizar:

  • Consultar as APIs de PDDE/PNAE/Execucao Orcamentaria
  • Formatar como arrays JavaScript
  • Substituir as constantes PDDE_CACHE, PNAE_CACHE, EXEC_CACHE no arquivo
🚀 Passo a Passo de Replicacao
  • Copiar index.html para o servidor de destino
  • As abas PDDE/PNAE/Execucao funcionam imediatamente (dados embarcados)
  • A aba Compras requer internet (API PNCP + proxy CORS)
  • Para ambiente corporativo: configurar proxy CORS proprio no lugar do allOrigins
  • Classificador de setores usa 14 grupos de palavras-chave — ajustar conforme necessidade local
⚠️ Problemas Conhecidos
O arquivo tem 6.8 MB devido aos caches embarcados. Considerar externalizar os caches em arquivos JSON separados para melhor performance. A paginacao da API PNCP e limitada a 5 paginas (250 resultados por modalidade).

  • Dados estaticos: data/rf_empresas.json (21 KB, dados RF por setor/UF)
  • Pipeline Python: scripts/gerar_dados_rf.py (consulta OLAP Tesseract)
  • CI/CD: GitHub Actions (semanal) + GitLab CI (deploy Pages)

🔗 Fontes de Dados
FonteURL BaseAutenticacaoDados
Camara dos Deputadosdadosabertos.camara.leg.br/api/v2NenhumaProposicoes, orgaos, deputados, autores, tramitacoes
Senado Federallegis.senado.leg.br/dadosabertosNenhumaMaterias atualizadas, pesquisa, movimentacoes
Observatorio OLAP (Tesseract)apiv2-observatorio.sebrae.com.br/tesseractToken APICubo RF: empresas ativas por setor/UF/porte

  • Frontend: Chart.js 4.4.4 (CDN jsDelivr)
  • Python: requests (para o script de dados RF)
⚡ Pipeline de Dados

scripts/gerar_dados_rf.py consulta a API OLAP do Observatorio Sebrae (cubo RF) e gera data/rf_empresas.json com dados de empresas ativas por setor e estado.

GitHub Actions executa semanalmente (segunda-feira 06:00 UTC) e faz auto-commit dos dados atualizados.

🚀 Passo a Passo de Replicacao
  • Clonar o repositorio pippa-sebrae
  • Configurar variavel de ambiente OBSERVATORIO_TOKEN com token da API OLAP
  • Executar pip install requests && python scripts/gerar_dados_rf.py
  • Servir o diretorio via servidor HTTP (python -m http.server) — necessario para o fetch() do JSON
  • Clicar em "Consultar APIs" no dashboard para buscar dados legislativos em tempo real
  • Configurar GitHub Actions para atualizacao semanal automatica do JSON de RF
⚠️ Problemas Conhecidos
O Senado limita consultas a 60 dias (parametro numdias). Consultas com intervalos maiores sao silenciosamente truncadas. O script Python tem um token de fallback hardcoded — substituir por variavel de ambiente em producao.

  • Motor de classificacao em 3 eixos: relevancia direta MPE (0-0.5), alcance setorial (0-0.3), potencia normativa (multiplicador)

✅ Checklist de Implantacao

Verificacao para Cada Ferramenta

  • ☐ Repositorio clonado e arquivos acessiveis
  • ☐ Servidor HTTP configurado (GitHub Pages, GitLab Pages, Nginx, etc.)
  • ☐ CDN Chart.js acessivel (testar cdn.jsdelivr.net na rede corporativa)
  • ☐ Google Fonts acessivel (testar fonts.googleapis.com)
  • ☐ APIs externas acessiveis (sem bloqueio de firewall corporativo)
  • ☐ Token OLAP configurado (se ferramenta usa Observatorio Tesseract)
  • ☐ Proxy CORS configurado (se ferramenta usa DOU ou PNCP cross-origin)
  • ☐ Python + dependencias instalados (se ferramenta tem pipeline)
  • ☐ Pipeline executado e dados gerados com sucesso
  • ☐ Dashboard aberto no navegador e funcionalidades testadas
  • ☐ Filtros operando corretamente
  • ☐ Links de navegacao (Portal, Quem Somos) apontando para URLs corretas
