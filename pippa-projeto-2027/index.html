Visão do Produto
Product Vision Statement

Para o Sistema Sebrae (27 estados + Nacional), gestores públicos e o ecossistema de políticas para MPEs,
que necessitam de inteligência baseada em evidências para formular, monitorar e avaliar políticas públicas,
a PIPPA é uma plataforma integrada de inteligência, experimentação e advocacy em políticas públicas aplicadas
que transforma dados de 36 cubos OLAP e 23+ fontes em insights acionáveis, laboratórios de experimentação e incidência legislativa qualificada,
diferente de observatórios tradicionais que apenas publicam indicadores sem aplicação prática,
a PIPPA conecta o ciclo completo: observar → compreender → aplicar → transformar — da inteligência de dados à mudança de política pública.

🔭 PIPPA Nacional
Hub estratégico de inteligência. Ferramentas de análise, monitoramento legislativo, orçamentário e regulatório. Visão consolidada do ambiente de negócios para MPEs em escala federal.
🗺️ PIPPA Estadual
Cada UF replica o modelo PIPPA PB em seu território, customiza dashboards, integra dados locais e constrói suas próprias ferramentas na plataforma.
🧪 PIPPA Aplicada
TransformaLab (3 modelos de laboratório), Advocacy e Incidência legislativa — da evidência à ação pública. Alinhado à Cartilha LPP do Sebrae.

Product Backlog — Epics e Features
Organizado por eixo e prioridade (MoSCoW)

🔭 Eixo Nacional — Epics

MUST EP-01: Design System e Padronização Visual
  • F-01.1: Criar biblioteca de componentes reutilizáveis (cards, tabelas, filtros, gráficos) no padrão PIPPA
  • F-01.2: Padronizar as 14 ferramentas existentes — identidade visual, responsividade, acessibilidade
  • F-01.3: Implementar design tokens (cores, tipografia, espaçamento) como variáveis CSS/JS
  • F-01.4: Templates de dashboard por persona (empresário, gestor público, analista, parlamentar)
  • Critério de aceite: Todas as ferramentas seguem o design system; auditoria visual passa sem FAIL
  • Responsável: UX Design Pleno + BI Pleno
MUST EP-02: Infraestrutura de Dados Unificada
  • F-02.1: Data lake centralizado no GCS/BigQuery com esquema de particionamento por cubo/UF/período
  • F-02.2: Pipeline de ingestão automatizada para os 36 cubos OLAP com cache inteligente e refresh programado
  • F-02.3: API unificada (FastAPI) para acesso aos dados — autenticação, rate limiting, documentação OpenAPI
  • F-02.4: Data Catalog — catálogo de metadados, linhagem, qualidade de dados, dicionário integrado
  • F-02.5: Arquitetura Mínima de Dados (Cartilha p.46) — bases empresariais, indicadores, socioeconômicos
  • Critério de aceite: Qualquer cubo acessível em <2s via API; linhagem rastreável de ponta a ponta
  • Responsável: Eng. Dados Sênior
MUST EP-03: Portal Redesenhado com 3 Eixos
  • F-03.1: Navegação reestruturada em 3 eixos (Nacional / Estadual / Aplicada) — visível e intuitiva
  • F-03.2: Busca semântica — pesquisa por intenção, não por nome de ferramenta (grafo de conhecimento)
  • F-03.3: Dashboard de overview (stat tiles nacionais) — Shneiderman overview first
  • F-03.4: Área do estado — cada UF acessa suas ferramentas e dados territoriais
  • F-03.5: Onboarding guiado — jornada do primeiro acesso
  • Critério de aceite: Qualquer usuário encontra o que precisa em ≤3 cliques; perguntas do sidebar cobrem 100% dos fluxos
  • Responsável: UX Design Pleno + BI Pleno
MUST EP-04: Automação de Pipelines de Dados
  • F-04.1: Orquestração com Prefect/Cloud Scheduler — pipelines de emendas, legislativo, regulatório, indicadores em schedule
  • F-04.2: Alertas de falha e degradação — Slack/email para o time quando pipeline quebra
  • F-04.3: Validação de qualidade de dados — checks automáticos pós-ingestão (schema, null rates, anomalias)
  • F-04.4: Refresh incremental — apenas dados novos, não full load
  • Critério de aceite: Zero intervenção manual para atualização diária/semanal dos dashboards
  • Responsável: Eng. Dados Sênior
SHOULD EP-05: Agente IA Conversacional Avançado
  • F-05.1: Interface conversacional no portal — chat que consulta cubos, gera gráficos, cruza dados
  • F-05.2: RAG sobre base de conhecimento PIPPA (Cartilha LPP, livro, Nota Técnica, documentação dos cubos)
  • F-05.3: Roteamento inteligente — classifica intenção e direciona para ferramenta/cubo correto (semantic_routing.yaml)
  • F-05.4: Geração de relatórios automatizada por persona (7 templates existentes)
  • F-05.5: Multi-modelo — fallback entre Gemini, Claude, Barramento Sebrae conforme disponibilidade
  • Critério de aceite: Agente responde corretamente 85%+ das perguntas sobre os 36 cubos
  • Responsável: Eng. Dados Sênior
SHOULD EP-06: Modelos Preditivos e ML
  • F-06.1: Clustering de municípios por vocação econômica (RF + ECI + RCA + COMEX)
  • F-06.2: Previsão de impacto legislativo — NLP sobre textos de PLs + histórico de tramitação
  • F-06.3: Detecção de anomalias em emendas — padrões atípicos de execução/concentração
  • F-06.4: NLP no DOU — classificação setorial automatizada (evolução do pipeline Gemini atual)
  • F-06.5: Série temporal — projeção de indicadores de ambiente de negócios por UF
  • Critério de aceite: Pelo menos 3 modelos em produção com métricas de performance publicadas
  • Responsável: Eng. Dados Sênior

  • F-10.3: Admin panel — gestão de usuários, permissões, dados locais

  • Responsável: Eng. Dados Sênior + UX Design Pleno

Cadência
  • Sprint: 2 semanas (10 dias úteis)
  • Release: trimestral (4–5 sprints por release)
  • 17 sprints no ano (jan–nov), dezembro = buffer
  • Velocity estimada: ~40 story points/sprint (calibrada após Sprint 3)
  • WIP limit: máximo 2 features em andamento por dev (Kanban dentro do Scrum)
Definition of Done (DoD)
Uma feature só é considerada "Done" quando:
  1. Código: revisado via merge request (pelo menos 1 aprovação), sem warnings de lint
  2. Testes: unitários passando, testes de integração para APIs/pipelines
  3. Visual: auditoria visual passa sem FAIL (skill /visual-auditor)
  4. Metodologia: segue os 5 eixos do livro — Shneiderman, storytelling, elemento gráfico adequado
  5. Dados: pipeline reprodutível (/validacao), dados reais (zero dados sintéticos)
  6. Deploy: em staging sem erros, validado pelo PO
  7. Documentação: README atualizado, knowledge base atualizada se novo cubo/fonte
  8. Acessibilidade: responsivo, contraste adequado, navegável por teclado

Diagnóstico Atual e Meta por Dimensão
Cada dimensão parte de um nível real (baseado no que a PIPPA já possui) e evolui conforme os epics avançam:
Nível 2→5 Infraestrutura

Hoje (nível 2): 14 ferramentas HTML funcionais hospedadas no GitHub Pages, mas sem CI/CD, sem ambientes separados, sem IaC. Deploy é manual.

Meta (nível 5): GitLab CI/CD com deploy automático, ambientes dev/staging/prod, IaC para replicação estadual em <1 dia, monitoramento com alertas, rollback em <5 min.

Salto principal: R1 (CI/CD + design system) e R2 (IaC estadual).

Nível 3→5 Dados

Hoje (nível 3): 36 cubos OLAP acessíveis, 23+ APIs integradas, 114 MB de dados de emendas processados. Porém os pipelines são manuais, não há data lake centralizado nem catálogo de metadados.

Meta (nível 5): Data lake no GCS/BigQuery, pipelines automatizados com Prefect, refresh incremental, Data Catalog com linhagem, validação de qualidade pós-ingestão.

Salto principal: R1 (data lake + pipelines) e R3 (modelos ML sobre os dados).

Nível 2→5 Inteligência

Hoje (nível 2): Agente IA existente (agente.py com deepagents), 18 ferramentas-tool, roteador de tarefas, RAG básico com Vertex AI. Porém sem interface pública, sem modelos preditivos, sem NLP avançado.

Meta (nível 5): Agente conversacional no portal, RAG sobre toda a base de conhecimento, 3+ modelos ML em produção (clustering, previsão legislativa, anomalias), NLP avançado no DOU.

Salto principal: R2 (agente + RAG público) e R3 (modelos ML).

Nível 3→5 Metodologia

Hoje (nível 3): Metodologia do livro definida e aplicada nos dashboards existentes (Shneiderman, storytelling, pipeline Card et al). Design system emergente mas não formalizado. Cartilha LPP publicada.

Meta (nível 5): Design system completo com componentes reutilizáveis, templates por persona, framework TransformaLab com 3 modelos de lab operacionais, DoD com auditoria metodológica.

Salto principal: R1 (design system) e R3 (TransformaLab com 3 modelos).

Nível 1→5 Comunidade

Hoje (nível 1): Apenas o protótipo da Paraíba (PIPPA PB) em produção. Nenhuma UF com instância própria. Sem trilha de capacitação. Equipe restrita à UPP.

📖 Livro — Modelo Conceitual de VI em OI

"Visualização da Informação em Ambientes de Divulgação de Dados Abertos" (Albuquerque, Dialética, 2024)

  • 5 eixos: Infraestrutura, Usuário, Metodologia, Design, Técnicas de VI
  • Pipeline: Dados brutos → Tabela → Elementos visuais → Visão (Card et al, 1999)
  • Shneiderman: Overview first, zoom and filter, details on demand
  • Storytelling: Narrativa visual guiada, não gráficos soltos
  • Anti-padrões: Excesso de pizza, 3D, dual-axis, subutilização de mapas
  • Maturidade OI: 6 eixos (Gomes et al, 2016) — critério de avaliação
📘 Cartilha LPP — TransformaLab

"Cartilha LPP — Laboratório de Políticas Públicas" (Sebrae Nacional, 2026)

  • Modelo triangular: OPP + LPP + Advocacy — três iniciativas complementares
  • Hub TransformaLab: 4 funções (Liderança, Rede, PP, Dados)
  • 3 modelos de lab: Design e Experimentação, Pró-Negócios, Insight Lab
  • 6 estágios de implantação com gates de aprovação
  • Capacidades dinâmicas: 348h, 12 meses, 3+1 trilhas

📖 Glossário Completo
Metodologia Ágil
Scrum — Framework ágil iterativo e incremental para gestão de projetos complexos. Organiza o trabalho em ciclos curtos (sprints) com papéis definidos, cerimônias e artefatos.
Sprint — Ciclo de trabalho de duração fixa (neste projeto: 2 semanas). Cada sprint produz um incremento potencialmente entregável do produto.
Product Owner (PO) — Responsável por maximizar o valor do produto. Define prioridades do backlog, aceita ou rejeita entregas. No PIPPA: Julio Enders.
Scrum Master — Facilitador do processo ágil. Remove impedimentos, garante que o time siga as práticas Scrum. No PIPPA: papel rotativo entre os membros.
Sprint Planning — Cerimônia no início de cada sprint onde o time seleciona itens do backlog e planeja como executá-los durante o ciclo.
Daily Standup — Reunião diária breve (15min) para sincronização. Cada membro diz: o que fez, o que fará, se há impedimentos. No PIPPA: assíncrona via Slack.
Sprint Review — Cerimônia ao final da sprint onde o time demonstra o que foi construído aos stakeholders e coleta feedback.
Sprint Retrospective — Reunião de melhoria contínua após cada sprint. O time reflete sobre o que funcionou, o que não funcionou e o que pode ser melhorado.
Backlog Refinement — Sessão onde o PO e o time detalham, estimam e priorizam itens do backlog para sprints futuras.
Release — Versão entregável do produto. Agrupa múltiplas sprints. No PIPPA: 4 releases trimestrais (R1 a R4) com gates de aprovação.
Release Planning — Planejamento trimestral de alto nível. Define os epics e features que serão entregues na próxima release.
Demo Day — Evento de demonstração ao final de cada release para stakeholders amplos. Mostra o que foi construído e coleta feedback estratégico.
Epic — Bloco grande de trabalho que agrupa múltiplas features relacionadas. Representa uma capacidade significativa do produto (ex: EP-02: Infraestrutura de Dados Unificada).
Feature — Funcionalidade específica e entregável dentro de um epic. Tem critério de aceite próprio (ex: F-02.3: API unificada FastAPI).
Story Point (SP) — Unidade de estimativa de esforço relativo para uma tarefa. Não mede tempo — mede complexidade, incerteza e volume de trabalho.
Velocity — Quantidade de story points que o time entrega por sprint, em média. Serve para prever capacidade futura. Meta PIPPA: ≥ 35 SP.
Cycle Time — Tempo médio que uma feature leva do início do trabalho (In Progress) até ser concluída (Done). Meta PIPPA: ≤ 5 dias úteis.
Lead Time — Tempo total de uma feature desde que entra no backlog até chegar em produção. Inclui tempo de espera. Meta PIPPA: ≤ 3 sprints.
Burndown Chart — Gráfico que mostra o trabalho restante (story points) ao longo da sprint. Tendência ideal: linha descendente linear.
Burnup Chart — Gráfico que mostra as features entregues vs. planejadas ao longo de uma release. Permite visualizar progresso e escopo.
WIP Limit (Work In Progress) — Restrição de quantas tarefas podem estar em andamento simultaneamente. No PIPPA: máx 2 features por dev. Previne multitarefa excessiva.
Definition of Done (DoD) — Checklist de critérios que toda feature deve atender para ser considerada concluída: código revisado, testes passando, visual auditado, deploy em staging, etc.
MoSCoW — Técnica de priorização: Must (obrigatório), Should (importante), Could (desejável), Won't (fora do escopo). No PIPPA: 9 MUST, 5 SHOULD, 1 COULD.
Gate — Ponto de decisão ao final de cada release. O PO e stakeholders avaliam as entregas e decidem se o projeto avança para a próxima fase.
Kanban — Método visual de gestão de fluxo de trabalho com colunas (Backlog → To Do → In Progress → Review → Done). No PIPPA: usado dentro do Scrum.
RACI — Matriz de responsabilidades: Responsible (executa), Accountable (aprova), Consulted (consultado), Informed (informado). Define quem faz o quê por epic.
OKR (Objectives and Key Results) — Framework de metas: Objetivo (qualitativo, inspiracional) + Key Results (quantitativos, mensuráveis). No PIPPA: 4 objetivos com 3 KRs cada.
NPS (Net Promoter Score) — Métrica de satisfação de 0 a 10. Pergunta: "Qual a probabilidade de recomendar?" No PIPPA: NPS interno das UFs com a plataforma.
Merge Request (MR) — Solicitação de revisão e integração de código no GitLab. Toda alteração passa por MR com pelo menos 1 aprovação antes de ir ao branch principal.
Pair Programming — Prática onde dois desenvolvedores trabalham juntos no mesmo código: um escreve, outro revisa em tempo real. Usado na implantação das UFs piloto.
Dados, IA e Engenharia
Cubo OLAP — Estrutura multidimensional de dados pré-agregados para análise rápida. Permite consultas por dimensões (UF, ano, setor) e medidas (contagem, soma, média). O PIPPA usa 36 cubos via API Tesseract.
API (Application Programming Interface) — Interface que permite que sistemas se comuniquem. Ex: a API Tesseract do Observatório Sebrae fornece dados dos cubos OLAP via requisições HTTP.
REST API — Padrão de API web usando HTTP (GET, POST, etc.). A maioria das APIs de dados do PIPPA são REST (IBGE, BCB, Câmara, Senado, CGU).
FastAPI — Framework Python moderno para criação de APIs REST de alta performance. Gera documentação automática (OpenAPI/Swagger). Usado no backend PIPPA.
Data Lake — Repositório centralizado de dados brutos em diversos formatos. No PIPPA: Google Cloud Storage (GCS) como data lake, BigQuery como data warehouse.
Data Warehouse — Banco de dados otimizado para análise, com dados já estruturados e limpos. No PIPPA: BigQuery para consultas analíticas sobre dados processados.
Lakehouse — Arquitetura que combina a flexibilidade do data lake (dados brutos) com a performance do data warehouse (dados estruturados). Abordagem do PIPPA com GCS + BigQuery.
Pipeline de Dados — Fluxo automatizado que coleta dados de fontes, transforma, valida e carrega no destino (ETL/ELT). No PIPPA: scripts Python orquestrados por Prefect/Cloud Scheduler.
ETL (Extract, Transform, Load) — Processo de extração de dados de fontes diversas, transformação (limpeza, enriquecimento) e carga em destino estruturado.
Parquet — Formato de arquivo colunar otimizado para análise de grandes volumes de dados. Compacto e rápido. Usado nos dados processados do PIPPA.
Data Catalog — Inventário organizado de todos os ativos de dados: tabelas, APIs, cubos, com metadados, linhagem e qualidade. No PIPPA: Google Data Catalog.
Linhagem de Dados — Rastreabilidade de ponta a ponta: de onde veio cada dado, por quais transformações passou, onde é usado. Essencial para auditoria e confiança.
LLM (Large Language Model) — Modelo de linguagem treinado em grandes volumes de texto. Ex: Gemini, Claude, Qwen. No PIPPA: usado para classificação do DOU, agente conversacional e RAG.
RAG (Retrieval-Augmented Generation) — Técnica que combina busca em base de conhecimento com geração de texto por LLM. O agente PIPPA usa RAG para responder sobre cubos, Cartilha e livro.
NLP (Natural Language Processing) — Processamento de linguagem natural por computador. No PIPPA: classificação de normas do DOU, análise de textos legislativos, busca semântica.
ML (Machine Learning) — Aprendizado de máquina — algoritmos que aprendem padrões a partir de dados. No PIPPA: clustering de municípios, previsão de impacto legislativo, detecção de anomalias.
Clustering — Técnica de ML que agrupa dados similares automaticamente. No PIPPA: agrupar municípios por vocação econômica usando dados de RF, ECI e COMEX.
Embeddings — Representações numéricas (vetores) de textos ou conceitos. Permitem busca semântica — encontrar conteúdos similares por significado, não por palavras exatas.
Vector Store / Vector Search — Banco de dados otimizado para busca por similaridade de vetores (embeddings). No PIPPA: Vertex AI Vector Search e ChromaDB.
IaC (Infrastructure as Code) — Prática de definir infraestrutura (servidores, bancos, configs) como código versionável. No PIPPA: script que provisiona instância estadual completa automaticamente.
CI/CD (Continuous Integration / Continuous Delivery) — Práticas de automação: CI integra e testa código automaticamente a cada commit; CD automatiza o deploy para staging/produção. No PIPPA: GitLab CI/CD.
RBAC (Role-Based Access Control) — Controle de acesso baseado em papéis. Cada usuário tem um papel (admin, analista, viewer) que determina o que pode acessar na plataforma.
LGPD — Lei Geral de Proteção de Dados (Lei 13.709/2018). Define regras para tratamento de dados pessoais no Brasil. O PIPPA trata dados agregados para compliance.
Tecnologias e Ferramentas
BigQuery — Data warehouse serverless do Google Cloud. Permite consultas SQL sobre petabytes de dados. No PIPPA: armazenamento centralizado dos cubos processados.
GCS (Google Cloud Storage) — Serviço de armazenamento de objetos na nuvem. No PIPPA: bucket "ucomp-na" como data lake para documentos, dados brutos e arquivos.
Cloud Run — Serviço serverless do GCP que roda containers. No PIPPA: hospedagem de APIs FastAPI sem gerenciar servidores.
Cloud Functions — Funções serverless acionadas por eventos (HTTP, schedule, upload). No PIPPA: pipelines de ingestão e transformação de dados.
Vertex AI — Plataforma de IA do Google Cloud. No PIPPA: Search (busca RAG), Vector Search (busca semântica), embeddings (text-embedding-005).
Cloud Scheduler — Serviço de agendamento do GCP. No PIPPA: dispara pipelines de atualização de dados em horários programados (diário/semanal).
Secret Manager — Serviço do GCP para armazenar credenciais de forma segura. No PIPPA: tokens de API, senhas de banco, chaves — zero credenciais em código.
Gemini — Família de modelos LLM do Google (Flash = rápido e barato, Pro = mais capaz). No PIPPA: modelo padrão do agente IA e classificação do DOU.
Claude — Família de modelos LLM da Anthropic (Sonnet, Opus). No PIPPA: fallback do agente IA e assistência ao desenvolvimento.
Barramento vLLM (Sebrae) — Infraestrutura interna do Sebrae que hospeda modelos de IA open-source (Qwen, Gemma, Mistral) para uso corporativo via API OpenAI-compatible.
LangChain — Framework Python para construção de aplicações com LLMs. Permite encadear prompts, ferramentas e memória. No PIPPA: orquestração do agente IA.
deepagents — Biblioteca de agentes IA autônomos. No PIPPA: permite que o agente IA execute tarefas complexas (consultar cubos, gerar gráficos, cruzar dados).
ChromaDB — Banco de dados vetorial open-source e local. No PIPPA: armazenamento de embeddings para o radar de fomento.
Prefect — Plataforma de orquestração de pipelines de dados. Alternativa moderna ao Airflow. Permite scheduling, retry, monitoramento de fluxos.
GitLab — Plataforma DevOps completa: repositório Git, CI/CD, issues, boards, wiki, merge requests. No PIPPA: ferramenta central de versionamento e automação.
GitLab Flow — Estratégia de branches: main (desenvolvimento) → staging (homologação) → produção, com feature branches para cada feature.
GitHub Pages — Serviço de hospedagem de sites estáticos do GitHub. No PIPPA: hospedagem dos dashboards HTML single-file.
Figma — Ferramenta de design de interfaces (UI/UX) colaborativa. Usada pela equipe de UX do PIPPA para prototipar o design system e interfaces.
Tesseract (Observatório Sebrae) — Engine OLAP que serve os 36 cubos do Observatório Sebrae via API REST. Permite agregações multidimensionais sob demanda.
SQL Server — Banco de dados relacional da Microsoft. No Sebrae: 4 bancos internos (DW Atendimento, LEME, SME, RF) acessíveis via VPN.
Domínio PIPPA e Sebrae
PIPPA — Plataforma de Inteligência em Políticas Públicas Aplicadas. Iniciativa do Sebrae Nacional dividida em 3 eixos: Nacional, Estadual e Aplicada.
UPP — Unidade de Políticas Públicas do Sebrae Nacional. Área responsável pela estratégia e gestão da PIPPA.
ARP 027/2025 — Ata de Registro de Preços do SEBRAE/CE com a Qualificar TI. Contrato que define valores/hora para profissionais de TI em 7 áreas de serviço e 4 níveis de senioridade.
PE 2035 / Missão B — Planejamento Estratégico do Sebrae 2035. Missão B: "Governo e Estado Empreendedor por um Ambiente de Negócios Atrativo". A PIPPA está alinhada a esta missão.
MPE — Micro e Pequena Empresa. Público-alvo do Sebrae e foco de impacto de todas as análises e políticas monitoradas pelo PIPPA.
TransformaLab — Laboratório de Políticas Públicas do Sebrae. Plataforma de experimentação em PP com 3 modelos: Lab Design e Experimentação, Lab Pró-Negócios e Insight Lab. Definido na Cartilha LPP.
OPP (Observatório de Políticas Públicas) — Componente do modelo triangular da Cartilha LPP. Função de observar, monitorar e analisar políticas. No PIPPA: corresponde ao eixo Nacional.
LPP (Laboratório de Políticas Públicas) — Componente do modelo triangular. Função de experimentar, prototipar e testar políticas em ambiente controlado. No PIPPA: TransformaLab no eixo Aplicada.
Advocacy — Ação de influência qualificada em políticas públicas, baseada em evidências. No PIPPA: integrado ao eixo Aplicada e ao Parlamento Empreendedor.
Incidência — Ação direta de influência sobre o processo legislativo ou regulatório. Diferente de advocacy genérica, a incidência é pontual e estratégica: um PL, uma emenda, uma norma.
Parlamento Empreendedor — Iniciativa do Sebrae para engajar parlamentares na agenda de melhoria do ambiente de negócios para MPEs. Consome evidências da PIPPA para advocacy legislativa.
Cartilha LPP — Documento oficial do Sebrae (104 páginas, 2026) que define o conceito, framework e metodologia de implantação dos Laboratórios de Políticas Públicas (TransformaLabs).
Hub TransformaLab — Estrutura de governança do TransformaLab com 4 funções: Liderança, Gestão da Rede, Expertise em PP e Ciência de Dados.
Capacidades Dinâmicas — Conceito da Cartilha LPP: habilidades que organizações desenvolvem para adaptar-se a ambientes complexos. No PIPPA: plano de formação de 348h em 12 meses com 3+1 trilhas.
PIPPA PB (Paraíba) — Protótipo estadual da PIPPA implantado na Paraíba (pippa.sebrae.com.br). Modelo de referência para replicação nos demais estados.
Metodologia — Livro de Referência
Modelo Conceitual de 5 Eixos — Framework do livro de Julio Albuquerque (Dialética, 2024) para Visualização da Informação em Observatórios: Infraestrutura, Usuário, Metodologia, Design e Técnicas de VI.
Mantra de Shneiderman — "Overview first, zoom and filter, then details on demand." Princípio de design de VI que guia a estrutura dos dashboards PIPPA: stat tiles → cards → seções detalhadas.
Pipeline de Card et al (1999) — Modelo de transformação de dados em visão: Dados brutos → Tabela de dados → Elementos visuais → Visão. Referência central da metodologia PIPPA.
Storytelling com Dados — Técnica de comunicação que usa narrativa visual guiada para transformar dados em insights compreensíveis. Todo dashboard PIPPA conta uma história, não exibe gráficos soltos.
Observatório de Informação (OI) — Organização dedicada a coletar, analisar e disseminar dados e informações sobre um domínio específico. A PIPPA é um OI para políticas públicas voltadas a MPEs.
Maturidade de OI (Gomes et al, 2016) — Framework de avaliação de observatórios com 6 eixos: Inteligência, Metodologia, Comunidade, Dados, Infraestrutura e Governança.
Design System — Conjunto de componentes visuais padronizados (cores, tipografia, cards, gráficos) reutilizáveis. Garante consistência visual em todas as ferramentas PIPPA.
Overview + Detail — Técnica de VI que apresenta visão geral e detalhes simultaneamente em áreas separadas. Na PIPPA: stat tiles (overview) ao lado de gráficos detalhados.
Foco + Contexto (Fisheye) — Técnica de VI que amplia a área de interesse sem perder o contexto geral. Útil em mapas e visualizações de rede.
Anti-padrões de VI — Práticas de visualização a evitar: excesso de categorias em gráfico pizza, efeitos 3D, dual-axis (dois eixos Y), subutilização de mapas de calor e dispersão.
