PIPPA Legislativo — Radar de Proposições

Monitoramento de proposições legislativas com classificação automática P0–P4 (10 critérios) · APIs: Câmara dos Deputados + Senado Federal · pippa-legislativo-dashboard/index.html
UC-001 Consultar Proposições Legislativas por Período Analista UPP
Pré-condições

Dashboard PIPPA Legislativo v2.0 carregado no navegador. APIs da Câmara (dadosabertos.camara.leg.br/api/v2) e do Senado (legis.senado.leg.br/dadosabertos) acessíveis.

Fluxo Principal
  1. O analista seleciona data de início no campo dateInputInicio.
  2. O analista seleciona data de fim no campo dateInputFim.
  3. O analista clica no botão "Consultar APIs".
  4. O sistema valida as datas (ambas obrigatórias; fim >= início).
  5. O sistema executa 5 chamadas em paralelo (Promise.all):
    • API Câmara: /proposicoes?dataApresentacaoInicio=...&dataApresentacaoFim=... (paginação de 100/página)
    • API Senado: /materia/atualizadas (máx. 30 dias) e /materia/pesquisa/lista por sigla (PL, PLP, PEC, PDL, MPV)
    • Comissões ativas (permanentes codTipoOrgao=2, temporárias codTipoOrgao=3)
    • Lista de deputados (cache)
    • Tendência semanal (últimos 7 dias)
  6. O sistema separa proposições legislativas (PEC, PLP, PL, PDC, PDL, MPV) de documentos acessórios (PRL, EMR, EMP, EMC, REQ, RIC).
  7. O sistema classifica cada proposição via classifyRelevance() — 10 critérios com score numérico (ver UC-003).
  8. Proposições são ordenadas por prioridade (P0 primeiro) e exibidas com KPIs, gráficos e lista.
  9. Pós-classificação: o sistema busca autores/partidos em batch (10 paralelos) e situação/tramitação (5 paralelos).
Fluxos Alternativos
  • FA1 — Datas não selecionadas: O sistema exibe alert "Selecione data início e data fim".
  • FA2 — Data fim anterior à data início: O sistema exibe alert "Data fim deve ser >= data início".
  • FA3 — Timeout de API (30s): A chamada é silenciosamente ignorada; as demais chamadas continuam.
Pós-condições

Dashboard populado com proposições classificadas. KPIs exibem: total Câmara, total Senado, Relevantes Sebrae, P0+P1, P2 Monitorar. 6 gráficos Chart.js renderizados (prioridade, eixo, casa, comissões, tendência 7 dias).

Ferramenta: pippa-legislativo-dashboard/index.html · Função: fetchData()
UC-002 Filtrar e Buscar Proposições Analista UPP
Pré-condições

Dados de proposições carregados no dashboard (UC-001 concluído).

Fluxo Principal
  1. O analista expande uma seção de filtro clicando no header da seção.
  2. Seleciona um ou mais chips de filtro dentre 8 categorias:
    • Prioridade: P0, P1, P2, P3, P4
    • Relevância Sebrae: Central, Alta, Média, Baixa, Nula
    • Casa Legislativa: Câmara, Senado
    • Eixo Estratégico: 10 opções (Ambiente de negócios, MEI/Simples, Crédito, Compras públicas, Inovação, Educação, Territorial, Inclusão, Setorial, Sem conexão)
    • Tipo de Impacto: 8 opções (Direto MPE/MEI, Direto Sebrae, Indireto, Setorial, Corporativo, Social amplo, Processual, Sem impacto)
    • Papel do Sebrae: Incidência ativa, Monitoramento estratégico, Subsídio técnico, Monitoramento passivo
    • Institucional Sebrae/S: Sim, Não
    • Partido do Autor: Dinâmico, populado após busca de autores
  3. Filtros combinam com AND entre categorias e OR dentro de cada categoria.
  4. Dashboard atualiza KPIs, gráficos e lista de proposições simultaneamente.
  5. Badge numérico aparece em cada filtro ativo.
Fluxos Alternativos
  • FA1 — Limpar filtros: O analista clica "Limpar" em uma seção para remover todos os filtros daquela categoria.
  • FA2 — Busca textual: O analista digita no campo "Buscar ementa, autor, partido ou lei..." — busca em tempo real (oninput) nos campos ementa, sigla+número/ano, autor e partido.
  • FA3 — Sem resultados: O sistema exibe "Nenhuma proposição encontrada com esses filtros".
Pós-condições

Dashboard exibe apenas proposições que atendem todos os filtros aplicados. Todas as visualizações respondem simultaneamente.

UC-003 Classificar Proposição Automaticamente (10 Critérios) Sistema
Pré-condições

Ementa da proposição disponível. Dicionários KEYWORDS_CORE, EIXO_DEFINITIONS (8 eixos) e termos institucionais carregados.

Fluxo Principal
  1. O sistema normaliza o texto da ementa (NFD, remove acentos, lowercase).
  2. Verifica se a sigla é processual (REQ, RIC, RCP, MOC, INC, DVS, RQS, AVS) — se sim, classifica como P4/Nula.
  3. Busca matches em KEYWORDS_CORE (simples nacional, MEI, LC 123, etc.) usando word-boundary regex.
  4. Busca matches em EIXO_DEFINITIONS — 8 eixos estratégicos com keywords, broadKeywords e shortKeywords. broadKeywords só contam com contexto MPE presente.
  5. Busca matches institucionais (contribuição compulsória, lei 8029, etc.). Entidades (SESI, SENAI) só contam com contexto de governança (GOV_CONTEXT_TERMS). "sebrae"/"sistema s" sozinhos não ativam filtro institucional.
  6. Calcula score: (core × 3) + (eixo × 1) + (institucional × 4).
  7. Determina Relevância: Central (score >= 8) / Alta (>= 5) / Média (>= 2) / Baixa (>= 1) / Nula (0).
  8. Determina Prioridade: P0 (institucional) / P1 (Central ou Alta) / P2 (Média) / P3 (Baixa) / P4 (Nula).
  9. Atribui automaticamente: Tipo de Impacto (7 categorias), Papel do Sebrae (5 opções), Grau Siga Lei (5 níveis), Posicionamento default ("Neutro / em análise").
Pós-condições

Proposição classificada com 10+ atributos: prioridade, relevância, eixo, impacto, papel, institucional, score, keywords, grau Siga Lei, posicionamento.

Ferramenta: pippa-legislativo-dashboard/index.html · Função: classifyRelevance()

UC-016 Executar Pipeline de Coleta e Processamento de Emendas Administrador
Pré-condições

API FastAPI em execução (uvicorn na porta 8050). Nenhum pipeline em execução no momento.

Fluxo Principal
  1. O administrador envia POST /api/pipeline?ano=XXXX.
  2. O sistema verifica se pipeline_status["running"] é False.
  3. O pipeline executa em background:
    • Coleta: Download CSV do Portal da Transparência + Tesouro Transparente
    • Enriquecimento: Fetch parlamentares (APIs Câmara/Senado), resolução partido/UF via matching exato + fuzzy (rapidfuzz, threshold 85)
    • Filtro por ano: Opcional, via parâmetro ano
    • Validação cruzada: Compara totais por UF/ano entre Portal e Tesouro; flags OK (<5%), ALERTA (5–15%), CRÍTICO (>15%)
    • Persistência: Salva Parquets + relatório de qualidade JSON + agregações (por_estado, por_municipio, por_autor, por_partido, por_tipo, por_funcao, serie_temporal)
  4. O administrador consulta GET /api/pipeline/status para monitorar progresso.
Fluxos Alternativos
  • FA1 — Pipeline já em execução: O sistema retorna HTTP 409 com {"status": "Pipeline ja esta em execucao"}.
  • FA2 — Falha no pipeline: O campo last_error é preenchido com a mensagem; status retorna a running: false.
Pós-condições

Parquets atualizados em data/processed/. Relatório de qualidade em output/. Dashboard reflete dados atualizados.

Ferramenta: pippa-emendas/api.py · Endpoints: POST /api/pipeline, GET /api/pipeline/status, GET /api/dados

UC-021 Calcular e Visualizar ICP/RIG (Índice de Capital Político) Analista UPP
Pré-condições

Dados de parlamentares carregados com frentes e comissões.

Fluxo Principal
  1. O analista clica na aba "ICP/RIG".
  2. O sistema busca comissões do Senado via API (/senador/{id}/comissoes).
  3. Busca autorias temáticas via API Câmara (/proposicoes?keywords=...) com 12 keywords MPE em 4 batches.
  4. Identifica autores de cada proposição via /proposicoes/{id}/autores.
  5. Calcula PB (Pontuação-base, 0–100) em 5 dimensões:
    • A. Amplitude da Rede (0–20): frentes × 2 + comissões × 3
    • B. Profundidade (0–30): frentes Tier1 × 8 + Tier2 × 4 + comissões T1 × 10 + T2 × 5
    • C. Relevância Estratégica (0–20): posição em comissão + bônus (presidente +5, titular +3)
    • D. Articulação (0–20): autorias temáticas normalizadas
    • E. Inteligência Institucional (0–10): 2 pts cada (foto, email, frentes, comissões, dados eleitorais)
  6. Calcula MI (Multiplicador Institucional, 1–3×): ex. 2× para deputado eleito senador.
  7. Calcula BC (Bônus de Comissão, 1.00–1.35): por papel em comissão prioritária.
  8. Computa CP = PB × MI × BC e normaliza para ICP/RIG 0–100.
  9. Ranking ordenado por CP exibido com barras de progresso por dimensão.
Fluxos Alternativos
  • FA1 — Decomposição: O analista clica em um parlamentar no ranking para ver barras de progresso A–E, fórmula CP = PB × MI × BC com valores e justificativas (ex.: "Dep. eleito Senador 2026", "Titular CFT").
  • FA2 — Busca no ranking: O analista digita no campo "Buscar parlamentar no ranking ICP/RIG..." para filtrar por nome, partido ou UF.
Pós-condições

Ranking ICP/RIG com decomposição completa. KPIs: atores avaliados, PB médio, CP médio, MI elevado, BC ativo.
