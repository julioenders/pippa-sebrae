ClasseResponsabilidadeEstrategia
PartidoResolver Resolve partido e UF do autor da emenda via cruzamento com APIs Camara/Senado 1. Monta indice nome_normalizado para Parlamentar por legislatura
2. Para cada emenda, identifica a legislatura pelo ano (via ano_para_legislatura())
3. Busca autor por nome exato normalizado (unicode NFD, uppercase, whitespace normalization)
4. Se nao encontra, tenta fuzzy match via RapidFuzz (score >= 85)
5. Emendas de bancada/comissao/relator recebem flag NAO_APLICAVEL
6. Log de progresso a cada 10.000 emendas
IbgeNormalizer Preenche UF e regiao a partir do codigo IBGE quando ausentes Extrai os 2 primeiros digitos do codigo do municipio (7 digitos) para determinar a UF via tabela COD_UF_IBGE (27 mapeamentos). Preenche regiao via UF_REGIAO.

Total de campos em dataclasses44 (Parlamentar: 7, Emenda: 22, QualityFlag: 6, PipelineStats: 9)

Dimensoes do scoring ICP/RIG5 dimensoes (A-E) + 2 multiplicadores (MI, BC)
Padrao arquitetural: O backend Python segue uma arquitetura em camadas (Collectors -> Enrichment -> Pipeline -> API/Renderer) com heranca no modulo de coleta e composicao via CacheManager. O frontend JavaScript e funcional (funcoes de classificacao puras) com objetos de configuracao declarativos. Scripts de atualizacao sao procedurais e operam sobre estruturas dict tipadas. O scoring ICP/RIG combina coleta server-side (Python) com calculo client-side (JavaScript) via arquivo de cache intermediario.
